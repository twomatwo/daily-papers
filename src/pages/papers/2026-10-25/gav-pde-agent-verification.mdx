## 30-second takeaway

Coding agents can produce plausible PDE solver code, but **reliably checking it on new problems** can be more expensive than generating the code itself. **GAV (Generator–Agent–Verifier)** learns plausible continuous solution fields from numerical or experimental data and uses the **method of manufactured solutions** (MMS) to construct matching PDE source and boundary conditions *with a reference answer already known*. This supports unlimited new tests, continuous spatial queries, targeted difficult cases and numerical feedback. In the reported Navier–Stokes benchmarks, adapting three existing PDE agents to GAV improves their mean test errors by over an order of magnitude. Yet the generated problems are **manufactured physical test cases**, not newly discovered natural laws, and their usefulness depends on how closely the generator captures the target regime.

## Big Picture

**Before GAV:** a PDE agent evaluates code on a small set of fixed high-accuracy reference solutions. This can encourage accidental test adaptation and gives sparse feedback; making each new high-resolution ground truth from scratch is costly.

**With GAV:** learn a distribution of *solutions*, sample new smooth ones, construct the inputs that make each sample an exact solution, and evaluate the agent's program against it. A separate Verifier computes numerical discrepancy and runtime; it is not the LLM deciding whether its own answer is correct.

## Core mechanism: solve the PDE backward

In an ordinary PDE task, given a differential operator, forcing and boundary data, we compute an unknown solution. GAV instead **samples the reference first**:

```text
Given operator N_lambda and boundary operator B:

sample continuous u_ref from learned solution distribution

set source f := N_lambda[u_ref]
set boundary / initial data g := B[u_ref]

Now N_lambda[u_ref] = f and B[u_ref] = g by construction.
```

This is the **method of manufactured solutions**. The target solution can be evaluated or differentiated at many coordinates, allowing the Agent to decide where more precision or mesh resolution is necessary. It does not guarantee that a learned u_ref is an exact solution of an **unforced original PDE**; GAV defines a **new matched problem** with its own forcing and boundary conditions.

### Reliability: what the theory actually assumes

The main result bounds evaluation error for a **fixed candidate program**, assuming the learned distribution of manufactured problems is sufficiently close to the intended physical problem distribution. In Proposition 1 the assumption involves

```text
KL(P_target || P_generated) <= epsilon
```

plus sub-exponential tails for normalized losses and a finite independent test sample. The theorem does *not* assert that arbitrary adaptive agents are automatically unbiased by repeated evaluation on the same held-out sample, nor that the generator is physically exact when trained on partial noisy laboratory observations.

## Authors report vs AI interpretation

### Authors report

They demonstrate a general Generator–Agent–Verifier environment on Navier–Stokes and kinetic PDE tasks with numerical and experimental data sources. Continuous queries, data-informed generation and MMS contribute to solver development; they give theoretical conditions for fixed-program evaluation reliability. On numerical NS, reported improvements versus the original experimental environments of three agents are greater than tenfold in mean test error. Independent reference checks are reported to detect overfitting to the learned generator.

### AI interpretation

This is a particularly useful pattern for **AI-controlled materials simulations**: a coding agent should be able to request new *physically meaningful and verifiable* tests, not only run one script and trust its self-assessment. MMS is powerful because the test generator carries its own answer. The research opportunity is to adapt this to **diffusion, elasticity, spin/phase-field PDEs**, with precise audits of which boundary conditions and distributions represent actual microscope or transport measurements.

### Caveats

- **Manufactured answers are exact for manufactured inputs**, not necessarily independent truths for arbitrary real-world observations or the original PDE forcing.
- The guarantee relies on a *known bound* on distribution mismatch and a **fixed** program evaluated on independent tests. A real agent can adapt to the feedback and shift the distribution.
- Experimental references include model-based continuous reconstructions of discrete data, creating unavoidable interpolation and modeling choices.
- Benchmark improvements depend on numerical resolution, target regimes, evaluation points and time budgets; the comparisons are not evidence that GAV dominates all high-quality CFD software in general.
- The source is an **arXiv preprint**; experiments and theorem derivations were read, but **not independently reproduced**.

## Historical Reading Chain

1. **First read:** [Salari & Knupp (2000), Code Verification by the Method of Manufactured Solutions](https://doi.org/10.2172/759450). Exactly the technical trick behind free-to-verify constructed PDE problems.
2. [Li et al. (2025), CodePDE: An Inference Framework for LLM-driven PDE Solver Generation](https://arxiv.org/abs/2505.08783). A direct agent baseline showing how code generation, numerical tests and refinement previously worked.
3. [Raissi, Perdikaris & Karniadakis (2019), Physics-informed neural networks](https://doi.org/10.1016/j.jcp.2018.10.045). Offers a contrasting route that learns PDE solutions in a neural function representation, instead of coding solvers with a separate verifier.
