## 30 秒摘要

**Authors report：**研究者提出 Agentic-Teacher：给定一个已有 VLA checkpoint，先让它在模拟环境中执行任务、收集失败轨迹，再让 coding agent 识别关键干预状态，逐步编写和调试 closed-loop code policies，生成能从原 VLA 失败状态出发恢复任务的**成功演示**。作者发现，成功轨迹本身并不保证训练有效：还需要相关时间噪声、去除长时间 idle frames（保留 gripper changes）、以及使用冻结 VLA 的 flow-matching loss 过滤不合适的轨迹。由这些数据后训练所得 VLA **推理时不调用 coding agent**。

**作者仿真结果：**基模型 pi_0 在 LIBERO-10 从 79.4% 提高至 87.8%，MetaWorld-10 从 80.4% 至 90.6%，三个选择的 RoboCasa 任务平均从 0% 至 30%。与利用基模型自身成功轨迹的 RFT 基线相比，作者的外部 code-policy teacher 对几乎无成功轨迹的任务有独特价值。

**AI interpretation：**它把 agentic robotics 与 VLA post-training 连接起来：通用 Agent 负责在困难状态**搜索可执行恢复程序**，VLA 最终学习蒸馏后的 action distribution。研究提示，Agent 的工具、控制接口和验证能力是产生训练数据的资源，不能把结果简单归因于新 VLA 架构。

**Caveats：**所有主要结果是作者在模拟环境下报告的，尚未验证真实机械臂安全性、代码策略在 sim-to-real 中的可靠性、同等数据/算力预算下对所有竞争方法的优势。LIBERO 10 个任务有得有失，平均值不代表每项任务改善。

**阅读范围：**已核查 arXiv:2611.17394v1 HTML 的 Sections 1–6、Fig.1–6、主要表格、Appendices A–E 的相关实验/训练细则；没有运行 LIBERO、RoboCasa、训练脚本或实机实验。

## Big Picture：从失败中收集专门的教学样本

单纯模仿固定离线演示的 VLA，会在自己的 rollout 中进入分布外状态。基模型已经学会的任务可能不需要更多重复数据，反而是其**特定失效状态**最需要新的监督。

Agentic-Teacher 把这两件事分离：coding agent 负责搜索、诊断和生成 data，VLA 负责学习 compact, real-time policy。最终系统不是把 coding agent 直接装进每个 action-control cycle。

**AI-generated explanatory diagram（教学概念图，非原论文 Figure / 非定量数据）：**

> 原有 VLA policy pi_0 运行  \
> ↓  \
> 收集成功和失败 rollouts  \
> ↓  \
> Coding agent 定位关键失败帧、分析失败类型  \
> ↓  \
> 编写 closed-loop code policy → 仿真验证 → 失败则迭代  \
> ↓  \
> 成功修复的 trajectory generator  \
> ↓  \

> ↓  \
> 与基模型成功轨迹合并，进行 VLA post-training  \
> ↓  \
> 改进 VLA policy（**推理时不使用 coding agent**）

## 核心方法与公式

### 1. 针对失败状态而不是只重新生成漂亮的演示

作者从基模型尝试的 rollout 出发，寻找导致失败的局部关键状态，再写程序从该状态进行**闭环恢复**。代码执行的 simulator feedback/验证器帮助 agent 纠正自己的控制策略。验证通过的代码可反复用于相似状态，而不仅是某条静态轨迹。

和纯 Rejected Fine Tune（RFT）相比，当基模型无法成功完成任务时，RFT 可能几乎没有正样本，但 Agentic-Teacher 可以用外部 agent 寻找解。这一优势同时依赖 agent 的推理、工具、探索和仿真预算，必须在对照中明确。

### 2. 为什么要加入时间相关动作噪声？

代码策略往往走出比较理想化、光滑的成功路径。VLA 训练时只学习这条“细线”可能并不能在小扰动下回到轨迹。

作者加入时间相关噪声，使训练样本覆盖成功轨迹周围的可纠正状态。相比独立逐帧扰动，相关噪声更接近机器人执行中的连续控制误差。但噪声并不能无限加大：如果转移到完全无关的状态，成功监督反而会变差。

### 3. 为什么不是所有成功演示都值得用于 Flow Matching？

Flow matching VLA 学习从带噪动作走向 target action 的速度场。用概念化训练目标（并非逐字符复写作者每个实现细节）表示：

$$
\mathcal L_{\mathrm{FM}}
=
\mathbb E_{x,a,t,\epsilon}\,
\lVert v_\theta(x,a_t,t)-v^*(a,\epsilon,t)\rVert^2.
$$

一条代码轨迹在 simulator 中成功，并不意味着其连续动作序列与当前 VLA 的模型结构、状态访问和动作表示兼容。

因此作者使用**冻结的 base VLA flow-matching loss**评价候选演示，过滤较不适合当前 VLA 的样本。这使收集成功与生成**有用的后训练监督**成为两个独立标准。

另外，长时间 idle segments 的去除提高有效动作密度，但必须保留 gripper 的状态切换，不能简单逐帧采样以致抹去抓取释放的语义。

## Authors report：性能、消融与负面结果

### 在作者指定 simulation benchmark 上

| Benchmark | Base pi_0 | Rejected FT | Agentic-Teacher |
| --- | ---: | ---: | ---: |
| LIBERO-10 | 79.4% | 81.4% | **87.8%** |
| MetaWorld-10 | 80.4% | 85.2% | **90.6%** |
| RoboCasa（3 selected tasks） | 0% | 无基模型成功轨迹供 RFT | **30.0%** |

这些成功率来自作者的仿真任务，不能直接相加平均为“机器人平均成功率”，也不等于实体机器人完成率。每个 LIBERO-10 task 的最终测试包含 50 次 rollout。

### 平均提升并不意味着每个任务提升

论文 Appendix 的 per-task results 显示，某些任务退步，例如 LIBERO-10 的 book-caddy 从 96% 变为 88%、mug-microwave 从 78% 变为 56%；而 two-moka-stove 从 24% 提升至 78%。这类不均匀性非常值得在安全 benchmark 中保留。

### 消融不可和主要 benchmark 数字混为一谈

Fig.5 对同一套 trajectory processing 依次测试 raw code data、noise injection、idle removal 和 flow-matching filter。论文附录特别注明该消融在 **training step 4000** 评价，LIBERO 完整训练预算是 10000 steps。不要把 Fig.5 某个消融点与 Fig.4 的完整训练结果当成相同条件。

Fig.6 则比较成功样本**收集效率**，与最终训练模型的性能属于不同指标。

## Authors report vs AI interpretation vs caveats

### Authors report

- 失败驱动的 code-policy repair 可在模拟环境里生成针对 base VLA 薄弱状态的成功 demonstrations。
- 加入 correlated noise、清理 idle frame 和基模型 loss filtering 后，演示对于 VLA 后训练更有用。
- 在指定 LIBERO/MetaWorld/RoboCasa 仿真任务上，平均成功率高于论文所列基线。
- 一些任务没有改善，甚至出现成功率退步。

### AI interpretation

这为自动化机器人实验提供一条清晰路线：**昂贵的 Agent 可作为“教师/数据生成工厂”，低延迟的 VLA 仍负责实时闭环控制**。同时，它提示了一个可能值得研究的安全问题：如果 coding agent 以“任务完成”为唯一修复判据，可能学到碰撞风险较高的演示。因此安全约束应参与 trajectory validation、filtering 和 post-training evaluation，而不仅在推理末端加拒绝层。

这是应用推论，**不是作者已经验证的机器人安全改善结论**。

### Caveats

- 主要评测为仿真环境；没有提供独立的大规模真机安全复现。
- Coding agent 可用的工具、动作权限、仿真器和计算预算，会影响与纯 VLA/传统 RFT 的公平比较。
- “Causal frame localization” 是对轨迹错误位置的操作性诊断，不等于形式化因果识别或反事实证明。
- Agent 的脚本可以反复修复特定场景，但技能库可能难以覆盖新分布中的复杂失败。
- FM loss 过滤基于当前 frozen base policy；它是否会系统性排除真正创新但与现有策略差异很大的优秀轨迹，需要额外研究。
- RoboCasa 只有三个选定任务，不能外推到全套 benchmark。
- 成功率提升并不等同于实际伤害率、动作碰撞频次或危险环境下鲁棒性提升。
