## 30-second takeaway

Self-improving agents often summarize a completed task into a durable *lesson*, to guide later runs. But a **good decision can fail by chance**. Will a model-written lesson mistake unlucky execution for bad judgment? In this registered study, 11 LLM endpoints made **90,084** valid next-tool decisions across 256 synthetic worlds. After a chance failure of the **more reliable** tool, a failure-written lesson increased the rate of choosing the **worse** tool to **11.6%**, versus **0.4%** with an irrelevant memory item. A registered panel interaction was **+0.112** (95% interval **+0.097 to +0.126**). Prompt modifications partially reduced harm, but not uniformly across endpoints. The result concerns a **synthetic two-tool selection task**, not general real-world autonomous-agent safety.

## Big Picture: decision quality is not outcome quality

The basic failure mode is not an adversarial prompt injection. It is *ordinary experience summarization* under noisy outcomes.

A **good action** means choosing the tool with the better documented reliability given the information available **before** the outcome. That choice may still suffer a transient outage. If an LLM is instructed to distill the failed run into advice about what to avoid, a new session can inherit an unjustified preference for the less reliable tool. The authoritative log is still visible to that new session: this is about the weight and interpretation of the *memory item*, not withholding the original evidence.

**Counterfactual control:** supply a neutral memory item or a lesson written from a success, while holding the world and reliable run log fixed. The study measures differences between those reader arms.

## Experimental design: the intervention is a memory item

Across **256 synthetic worlds**, a task has two interchangeable tools with **recorded reliabilities**. A scripted previous run can choose the better (good decision) or worse (bad decision) tool, and the assigned outcome can be either success or transient failure. The model writes a lesson using an adapted released ReasoningBank instruction. A **fresh session of the same model** chooses a first tool with one controlled memory item; all other task information remains available.

Four cases are conceptually distinct:

```text
                   outcome: success   outcome: failure
 good decision       expected          unlucky / adverse
 bad decision        lucky / adverse   expected
```

The two adverse cells are asymmetrical: the damaging observation is strongest after a **good decision that failed**. The reverse case — a bad decision that luckily succeeded — produced a small registered interaction in this experiment. Do **not** infer a theorem that luck never matters after bad decisions.

Two important statistical quantities should not be confused:

- **Observed choice rates, Table 2:** in the good-decision/failure cell, **11.6%** chose the worse tool with a failure-written lesson, **0.4%** with neutral memory, and **0.4%** with a lesson from success.
- **Registered primary contrast P2, Table 1:** a difference-in-differences estimate of **+0.112**, with 95% interval **[+0.097, +0.126]** across the 256 worlds in the 11-endpoint panel. The contrast conditions on decision quality and outcome, controlling more factors than one rate subtraction.

The registered P3m estimate for the reverse adverse cell is approximately **+0.002**, interval **[-0.001, +0.005]**. The authors characterize this as bounded below the specified 0.10 margin, **not as proof of zero effect**.

## Why mitigation only partially solves the problem

The two tested alternatives were:

- **RBD:** ask the lesson writer to judge the original action by the **information available before the result**. The adverse cell's worse-tool choice rate fell from 11.6% to **7.5%**.
- **N:** use a common instruction after either outcome and explicitly allow **no change**. The rate fell to **3.1%**.

The registered panel-level harm reduction holds for both in the paper's comparisons, but neither helps every endpoint under the preregistered rule; the improvements are not a clean head-to-head causal test of which exact prompt feature matters. The study's evaluated reader still uses a logged synthetic reliability task, not an unrestricted real tool environment.

## Authors report

- A frozen protocol, archived preregistration and locked run records preceded the confirmatory call, making the reported comparisons auditable.
- In this experimental design, a failure-written lesson can transfer a chance outcome into the next tool choice, even when the next reader has the original authoritative evidence.
- Panel-level harm shows an asymmetry between **unlucky good decisions** and **lucky bad decisions** in the measured interaction.
- Two modest writing-instruction changes reduce but do not eliminate the measured rate on every model.

## AI interpretation

This paper makes a compelling case for treating an agent's persistent memory as **derived evidence, not ground truth**. A scientific Agent should record **pre-outcome decision rationale**, **observed outcome**, and **causal attribution confidence** as separate fields. It should be able to store: *"An apparent failure occurred; the evidence does not yet support changing the tool or protocol."*

For an automated laboratory, a single instrument timeout after an otherwise valid setup should trigger diagnosis of connectivity/reliability, not instantly a durable lesson that the measurement protocol is intrinsically wrong. Such workflow advice is an **AI extrapolation** from the paper, not a tested laboratory result.

## Caveats and alternative explanations

- The test is intentionally **synthetic**: two tools, explicit reliability information and a single first-tool decision. Multi-step real-world failures, hidden tool reliabilities, nonstationary reliability and actual downstream rewards were not established.
- Models write and read their own lessons; different endpoints' effects cannot isolate whether *writing* or *reading* was the weaker stage.
- The specific ReasoningBank **released code** prompts were adapted in declared ways. The paper does not test every memory architecture or even the exact printed instructions in the original ReasoningBank paper.
- Endpoint-specific comparisons are **exploratory and unadjusted across 11 endpoints**; the preregistered panel test and the separate model profiles should not be collapsed into one assertion.
- P3m being small is **not** a general guarantee of no harm after lucky bad decisions.
- The run records and statistical code were inspected through the paper's disclosures, **not independently reexecuted** for this guide.
- This arXiv v1 first appeared on **12 October 2026**; it is being recommended as a **recent backlog find**, not misrepresented as an October 28 release.

## Historical Reading Chain

1. **Read first:** [Baron & Hershey (1988), *Outcome bias in decision evaluation*](https://doi.org/10.1037/0022-3514.54.4.569). Understand why judging the original choice by its eventual luck corrupts reasoning, then map that bias onto the lesson writer.
2. [Ouyang et al. (2025), *ReasoningBank: Scaling agent self-evolving with reasoning memory*](https://arxiv.org/abs/2509.25140). This is the direct reference instruction/memory architecture adapted for the study.
3. [Shinn et al. (2023), *Reflexion: Language Agents with Verbal Reinforcement Learning*](https://arxiv.org/abs/2303.11366). Background on using language reflections as cross-run learning signals.
4. [Asadolahi et al. (2026), *Memory reward inflation in self-improving LLM agents*](https://arxiv.org/abs/2608.00017). A related diagnosis of how memory-writing loops can bias subsequent judgments.
